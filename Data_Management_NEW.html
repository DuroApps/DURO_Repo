How to generate a fine-scoped GitHub token:
  1. GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  2. Resource owner: pick your account or org. Repository access: Only select repositories → choose the one you set above.
  3. Repository permissions: set Contents to Read and write. Leave everything else read-only or no-access.
  4. Expiration: 90 days is reasonable. Set a calendar reminder to rotate.
  5. Copy the token (starts with github_pat_) and paste above. It is stored in this browser and in your Supabase project (admin-only row) — never in the repo.
Heads up: If the repository is public, the snapshot file is also public. The dashboard still requires Supabase login to render data — but the JSON is technically readable by anyone with the URL. For private repos, GitHub Pages requires a paid plan; consider hosting via Cloudflare Pages (free private) instead.

SQL Query Runner
Read-only by default (SELECT / WITH / EXPLAIN / SHOW only) · runs via the duroply_run_sql function — see setup note below
Result
One-time setup (run once in the Supabase SQL Editor):

Supabase's client library can't send raw SQL text directly — it talks to PostgREST, which only understands table/column calls. To let this box run arbitrary SQL, create this small helper function once (it restricts execution to read-only statements for safety):

create or replace function "DUROPLY".duroply_run_sql(query_text text)
returns jsonb
language plpgsql
security definer
set search_path = "DUROPLY", public
as $$
declare
  result jsonb;
  normalized text := lower(ltrim(query_text, chr(9)||chr(10)||chr(13)||chr(32)));
begin
  if not (
    normalized like 'select%' or
    normalized like 'with%'   or
    normalized like 'explain%' or
    normalized like 'show%'
  ) then
    raise exception 'Only SELECT / WITH / EXPLAIN / SHOW statements are allowed here.';
  end if;

  execute format('select coalesce(jsonb_agg(t), ''[]''::jsonb) from (%s) t', query_text)
  into result;

  return result;
end;
$$;

grant execute on function "DUROPLY".duroply_run_sql(text) to anon, authenticated;

Paste that into Supabase → SQL Editor → Run, once. After that, every query typed above executes live against DUROPLY and results render in the table. Since this uses security definer, it bypasses per-row RLS the same way a superuser query would — keep this tab restricted to Administrators (it already is, since it lives inside the Admin Panel), and don't loosen the SELECT-only check unless you're sure of what you're exposing.

Export Auth Users to CSV
Pulls accounts from Supabase Authentication (email, phone, sign-in activity) — admins only, never includes passwords
One-time setup (run once in the Supabase SQL Editor):

Authentication accounts live in Supabase's internal auth.users table, which the anon key can't read directly — by design, since it also stores password hashes. This function exposes only a safe, read-only slice of that table (no password/security-token fields) and checks the caller is an admin before returning anything:

create or replace function "DUROPLY".get_auth_users()
returns table (
  id                  uuid,
  email               text,
  phone               text,
  role                text,
  email_confirmed_at  timestamptz,
  last_sign_in_at     timestamptz,
  created_at          timestamptz,
  banned_until        timestamptz
)
language plpgsql
security definer
set search_path = auth, public
as $$
begin
  if not exists (
    select 1 from "DUROPLY".user_profiles
    where auth_id = auth.uid() and role = 'admin'
  ) then
    raise exception 'Only admins can export Authentication users.';
  end if;

  return query
    select u.id, u.email, u.phone, u.role,
           u.email_confirmed_at, u.last_sign_in_at, u.created_at, u.banned_until
    from auth.users u;
end;
$$;

grant execute on function "DUROPLY".get_auth_users() to authenticated;

Paste that into Supabase → SQL Editor → Run, once. The button above then calls this function and downloads the result as CSV — never the raw auth.users table, and never through the anon/public key.
